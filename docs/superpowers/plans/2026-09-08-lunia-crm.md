# Lunia CRM & Dashboards — Implementation Plan (Stage 5 of 7)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`).

**Goal:** The intelligence layer — client profiles with treatment history + per-visit therapist notes; a business dashboard (revenue, top services, new vs returning); a marketing/growth dashboard (CAC by channel, LTV, channel quality, booking conversion, traffic sources, top pages) powered by first-party analytics + campaign spend; and a filterable, exportable report center.

**Architecture:** Add `VisitNote`, `CampaignSpend`, and first-party analytics models (`PageView`, `AnalyticsEvent`); a lightweight privacy-preserving tracking beacon (`/api/track`) + client tracker; analytics/CRM read services building on the existing `bookingStats`; LTV maintained on `ClientProfile.ltvCacheMinor`; admin dashboards + client-profile screens + a report center with CSV export. All admin, permission-guarded.

**Tech Stack:** Existing repo stack. Reuse: `requireAdmin`/`AdminShell`/`DataTable`/`PageHeader`, `PERMISSIONS` (ANALYTICS_VIEW, MARKETING_MANAGE, CLIENT_VIEW, CLIENT_MANAGE, VISITNOTE_WRITE), `src/modules/booking/{stats,bookings}.ts`, `src/modules/booking/availability.ts` (center-local dates), catalog/settings services. Charts: render simple, dependency-light SVG/CSS bar/line charts (NO heavy chart lib unless trivial) or a tiny inline component — keep it premium and on-brand.

**Spec:** `docs/superpowers/specs/2026-09-07-lunia-platform-design.md` (§7 CRM/dashboards, §Marketing & Growth, §Business Dashboard).

## Global Constraints

- **Follow established patterns** — read before implementing: `src/modules/booking/stats.ts` (bookingStats — REUSE/extend), `src/app/admin/_components/*`, `src/app/admin/calendar/*` (admin data pages), `src/modules/iam/{rbac,permissions}.ts`, `src/modules/booking/availability.ts` (center-local day math for "today/this week/this month" in Asia/Riyadh), `prisma/seed.ts` (adapter + idempotent). Admin is English/LTR.
- **Money** integer minor units; **timezone** Asia/Riyadh for all "today/week/month" boundaries (reuse the availability tz helpers). **Revenue** = realized = sum of `priceMinorSnapshot` for COMPLETED appointments (document); show CONFIRMED/upcoming separately where useful.
- **Privacy:** first-party analytics stores NO PII — path, referrer host, UTM/source, an anonymous session id (random, cookie or localStorage), timestamp, locale. No cross-site tracking, no third-party. Respect Do-Not-Track by skipping tracking. The beacon is unauthenticated but validated + lightweight; never store IPs in plaintext beyond what's needed (prefer not storing raw IP at all).
- **Permissions guard-first** on every admin page/action: dashboards + reports = ANALYTICS_VIEW; campaign spend edit = MARKETING_MANAGE; client profiles view = CLIENT_VIEW, edit = CLIENT_MANAGE; visit notes write = VISITNOTE_WRITE. The tracking beacon (`/api/track`) is public (no auth) by necessity.
- **Correctness of the money/marketing math is paramount** — CAC = spend ÷ acquisitions for a channel in a period; LTV = realized revenue per client over lifetime; new vs returning by first-booking; conversion rate = bookings ÷ booking-funnel sessions (or ÷ pageviews of /book), documented. Test the aggregations.
- TS strict (no unjustified `any`), no emojis, conventional commits, TDD (unit for analytics/CRM services; e2e for the dashboards + client profile + export). Prisma migrations committed; seed idempotent. Charts must be accessible (data also available as a table/aria).

## Task 1: CRM/analytics schema + seed

**Files:** `prisma/schema.prisma`, migration, `prisma/seed.ts`, `tests/crm/model.test.ts`.

Models:
- `VisitNote` { id, clientProfileId (FK ClientProfile, cascade), bookingId? (FK Booking, set null), authorUserId (FK User), body String @db.Text, createdAt, updatedAt }.
- `CampaignSpend` { id, channel String, periodMonth String ("YYYY-MM"), amountMinor Int, note?, createdAt; @@unique([channel, periodMonth]) }.
- `PageView` { id, path String, locale String?, referrerHost String?, source String?, sessionId String, createdAt DateTime @default(now()) } (index on createdAt, path, source).
- `AnalyticsEvent` { id, name String (e.g. "booking_started","booking_completed"), path String?, sessionId String, meta Json?, createdAt } (index createdAt, name).
- Add `@@index([createdAt])` on `Booking` (the deferred perf item).

Seed (idempotent, small): a couple CampaignSpend rows (e.g. instagram/google for the current + prior month) so CAC has data.

- [ ] Add models + Booking index; migrate `--name crm`; generate; round-trip test; seed idempotent (2x). Commit `feat(crm): analytics + crm schema + seed`.

## Task 2: First-party analytics ingest (beacon) + tracker

**Files:** `src/modules/analytics/track.ts`, `src/app/api/track/route.ts`, `src/components/analytics/Tracker.tsx`, wire Tracker into the site layout, `tests/analytics/track.test.ts`.

- `track.ts`: `recordPageView({path, locale, referrerHost, source, sessionId})` + `recordEvent({name, path, sessionId, meta})` — validate/normalize (cap lengths, sanitize path to pathname only, derive referrerHost from a referrer URL, never store query strings with PII — keep only whitelisted `src`/utm as `source`). 
- `/api/track` (POST, public): accept a small JSON `{type:"pageview"|"event", path, source?, name?, referrer?, locale?, sessionId, meta?}`, validate (Zod), rate-limit lightly per sessionId (Redis), call track. Return 204. Ignore/skip if a DNT header is set. NEVER trust/echo input; store minimal fields.
- `Tracker.tsx` (client, mounted in the public `[locale]/(site)/layout.tsx`): on mount + on pathname change, generate/reuse an anonymous `sessionId` (localStorage/cookie, random), read `document.referrer` + the `?src`/utm from the URL, POST to /api/track (pageview). Skip when navigator.doNotTrack. Keep it tiny + non-blocking (sendBeacon/fetch keepalive). Also expose a helper to fire `booking_started`/`booking_completed` events from the booking wizard (optional wiring: fire booking_started when the wizard opens, booking_completed on success — wire in the wizard if cheap).

- [ ] TDD track.ts (recordPageView stores normalized row; a path with a query string is stored as pathname only; recordEvent stores). Beacon route test (POST pageview → 204 + a PageView row; DNT skips). Commit `feat(analytics): first-party tracking beacon`.
